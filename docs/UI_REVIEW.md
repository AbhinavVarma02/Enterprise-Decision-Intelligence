# UI review log

How the interface was checked and what changed as a result. Screenshots in `docs/screenshots/` are regenerated by `npm run screenshots` (Playwright, 1440x900 desktop, 820x1180 tablet, 390x844 mobile, full page).

## Method

1. Build the production bundle and serve it with `vite preview`.
2. Capture every page at the three viewports.
3. Look at each screenshot, then probe the DOM for horizontal overflow (`document.documentElement.scrollWidth` against the viewport width) on every route.
4. Run the browser journey tests (`e2e/journey.spec.ts`) on desktop and a Pixel 7 profile, including keyboard entry through the skip link.
5. Fix, rebuild, repeat.

The review questions were the ones the design system sets out (`docs/DESIGN_SYSTEM.md`): can a planner tell what to do and why within the first screen; is every number labeled as observed, estimated, simulated or assumed; does anything decorate rather than inform; does the page work one-handed on a phone.

## Pass 1: initial review

| Finding | Fix |
|---|---|
| Brand name and subtitle ran together in the rail | Brand lines set to block display |
| Menu button showed on desktop | Hidden above the mobile breakpoint |
| Decision selector pushed the page wider than the phone | Select limited to the container width; label row allowed to wrap |
| Key-value lists overflowed on the Overview and Data pages (long values in `dd.num`, which never wraps) | Columns made shrinkable; long values allowed to wrap |
| Visually hidden text inside scrolling tables escaped its container and widened the page | Table wrappers made the positioning context |
| Order quantities wrapped mid-line in the options table | Each supplier line rendered on its own row |

## Pass 2: editorial and layout refinement

**Options table (Decision workspace and Scenario studio).** The "change versus act now" column repeated what the expected-cost column already showed and pushed the spread chart off narrow screens. The difference now sits under each expected cost. "Arrives after the horizon" now says how many units, because the warning alone did not tell a planner whether it mattered.

**Selected row.** Only the data cells were highlighted, so the option name looked unselected. The whole row is highlighted now, with the accent bar on the first cell.

**Studio result table.** Its last column was clipped at desktop width because it shared a row with the summary. It now takes the full width under the summary.

**Charts.** Demand and stock charts were drawn at a fixed width and scaled to their panel, so their text shrank in narrow desktop panels and grew to about 25 px on a tablet, where the panel spans the page. Every chart now measures its container and redraws at the real width, so axis text stays at 11.5 px everywhere; stock bars stop widening past about 110 px per age group, and the "on hand" label moves below its line when it would sit on the forecast median. The benchmark charts also measure their container and redraw at the real width, so axis text stays at 11.5 px on a phone; the dot-and-whisker chart moves its labels above each row below 520 px, and the scatter chart nudges overlapping labels apart and keeps them inside the plot. Model names in the scatter are written out ("Quantiles, stockout-aware") instead of code identifiers, and ablation rows say what was removed.

**Tables on phones and tablets.** Wide tables scrolled sideways, hiding the cost columns that matter most. The two widest (benchmark detail with nine columns, forecast evaluation with seven) stack from 900 px down. On screens up to 640 px, tables in the workspace, overview queue, benchmark detail, audit, second domain, data checks, assumption register, forecast evaluation and decision history turn each row into a labeled two-column block. Stacked rows lay their values out in as many columns as fit (two on a phone, five on a tablet). Short three-column tables still render as tables. Option names in the options table were centered when they wrapped, because they are buttons; they are left-aligned now.

**Methodology flow.** The pipeline diagram was a fixed-width SVG that became unreadable on a phone. It is now an ordered list styled as a flow: four columns on desktop, two on tablets, one on phones. It is a real sequence, so the step numbers carry information.

**Wording.** The overview finding "total cost showed +0.8%" did not say which direction was good. It now states the effect in words and reports "no clear effect" whenever the 95% interval includes zero. Values that round to zero print as `0.0%` and `$0.00`, never with a sign.

## Pass 3: accessibility and robustness

- Faint text failed the 4.5:1 contrast minimum on the page background (see Known limits for the measurement). Darkened.
- The skip link was focusable but invisible when focused. It now appears at the top left on focus.
- The off-canvas navigation on phones stayed in the tab order while hidden, so keyboard users tabbed through invisible links. It is now hidden from focus until opened.
- The journey test had a race (pressing Tab before the app mounted). It now waits for the first heading.
- The journey test on mobile tried to click a navigation link that is off-canvas. It now uses the in-page link to the decision history, which is what a phone user would tap.

## Pass 4: automated accessibility scan

`e2e/a11y.spec.ts` runs axe-core (WCAG 2.0 and 2.1, levels A and AA) on all seven pages at desktop, phone (Pixel 7) and tablet (820 px) widths. The first run found one serious issue: on phones the Scenario studio's result table scrolled sideways inside a container that keyboard users could not reach. That table now stacks on phones, and any table wrapper that does overflow at the current width becomes a focusable, labeled region (only while it overflows). axe checks a subset of WCAG; screen-reader behavior has not been tested with a real screen reader.

## Independent audit pass

Payment Integrity informed the placement of uncertainty near the reported effect. Patient Outreach made the separation between modeled scenarios and observed evidence especially clear. Clinical Trace's screenshot sequence showed how workflow state and scope can stay visible on narrow screens. Enterprise Decision Intelligence uses its own IBM Plex typography, cobalt selection states, decision queue and aligned financial comparisons. [Payment Integrity](https://healthcare-payment-integrity.pages.dev/) · [Patient Outreach](https://patient-outreach-optimization.pages.dev/) · [Clinical Trace](https://github.com/AbhinavVarma02/Clinical-Trace-AI#clinical-workspace-screenshots)

The benchmark now opens with a source switch, a safety ledger and a keyboard-operable breach-cost slider. The Studio shows the best-scoring feasible order and separate validator verdict, with a concise result above the controls on narrow screens. The workspace distinguishes blocked submissions from executable alternatives. The data page identifies the observed-data pilot independently of synthetic cases. The history flow now supports verified export, clear, cancellation, re-import and validation of an external bundle's dimensions.

## Verified state

- No horizontal overflow on any route at 390 px or 820 px.
- 16 browser journey tests pass (desktop and mobile).
- 21 of 21 accessibility scans pass (7 pages x desktop, phone, tablet).
- 21 screenshots captured without errors.
- Bundle: 30 static files, about 1.04 MB in total, inside the 3 MB budget.

## Known limits

- The heat map in the Scenario studio is still a fixed grid; on a 390 px phone the cells are about 40 px wide, which is usable but tight.
- Charts are not keyboard-explorable. Every chart has an accessible name and the same numbers appear in an adjacent table or caption.
- Contrast was checked with the WCAG 2 formula for each text color on the backgrounds it sits on, not with an automated page scanner. That check found the faint text color (`#6f7983`) at 4.1:1 on the page background, below the 4.5:1 minimum; it was darkened to `#5f6872` (4.8:1 or better on every background it uses). Status chip text measures 4.6:1 to 5.9:1, and each chip pairs its color with a word and a dot.
